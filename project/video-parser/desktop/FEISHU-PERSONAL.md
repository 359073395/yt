# 个人飞书直连（开发验收中，尚未发布）

每人一套独立的飞书企业自建应用机器人。手机发消息 → 飞书 → 本人电脑。无需部署 `team-relay`，不填写公司收件服务地址，也不安装 Node/Python 助手。

扫码使用飞书官方应用注册 Device Flow：在官方页面创建个人专属机器人，不是抓取普通飞书账号 Cookie。一个应用不能同时分发给不同员工或多台运行中的电脑；飞书对同一应用的多个长连接随机投递，不按员工分流。

## 首次配置

1. 打开顶部“飞书自动下载”，确认电脑名称、视频保存位置，点击 **一键绑定飞书**。
2. 用手机飞书扫一扫，在飞书官方页面确认创建自己的“视频助手”。也可点击“在浏览器打开官方授权页”。不用填写任何 ID 或 Secret，不安装额外助手。企业禁止自行建应用或要求审批时，仍需管理员批准。
3. 保持影链工坊运行。授权后凭证自动在本机用 Windows DPAPI 加密保存。App Secret 和 device_code 不返回网页前端、不写日志或仓库。取消/过期会停止本机等待，但不会删除已在飞书创建的机器人。
4. 机器人会发送连接提示。向它回复 **连接测试**，或直接发送视频链接。实际收到你的私聊后才显示绑定完成，不能把“已获取凭证”当作“收件通过”。若没有提示，可在飞书搜索刚创建的机器人。凭证验证/权限错误会提示并自动重试，不要反复创建应用。
5. 完成收件验证后，打开“保存位置与选项”，确认视频保存目录及下载选项，点击目录下方的“保存并开启自动下载”。收件页顶部也始终显示开启/暂停开关；开关变为“自动下载已开启”才表示开始处理队列。视频保存位置和模型目录互不替代；语音模型和翻译接口沿用顶部“模型”配置，只保存视频和封面不需要下载翻译模型。

二维码有效期使用飞书实际返回值，界面显示倒计时；过期可重新生成。重新扫码不会覆盖已有应用，使用 `createOnly=true`。当前仅支持国内飞书，国际版 Lark 会明确提示不支持。

安全兜底：飞书授权响应如果没有返回扫码人的 `open_id`，才显示一次性配对码。向新机器人发送整行 `配对 XXXXXXXXXXXX`，然后在电脑确认本人。配对码 10 分钟过期；重启后可恢复配对码验证。不根据“第一个发消息的人”自动认领电脑。

权限范围：`addons.preset=false`，只请求 `im:message.p2p_msg:readonly`、`im:message:readonly`、`im:message:send_as_bot` 和 `im.message.receive_v1` 事件，不请求文档/联系人/员工表格权限。飞书模板的长连接和企业审批策略仍需真实扫码验收；如果事件无法投递，保留“等待收件验证”，不伪报完成。

程序只接受绑定账号与此机器人的私聊；群聊、其他账号及机器人消息不触发下载。配对前的历史不会自动导入。

## 日常发送

```text
分类 美妆/口播参考
备注 这个开头很好
https://www.tiktok.com/@作者/video/视频编号
```

中文分享文案不用清理；支持一条消息多个平台、多个链接，最多 50 条。视频链接需公开可访问；不同平台的登录、地区限制或风控仍可能导致下载失败。

- `分类：美妆/口播参考` → 保存根目录下的 `美妆/口播参考`。
- 仅写 `备注：好开头` → 保存到 `好开头`，同时保留备注。
- 没有分类或备注 → `待分类`。不适合作为文件夹名的长备注仍保留为备注。
- 可以回复原来的链接消息补发分类/备注；也可在电脑卡片中修改。
- 1.10.0 起分类与备注可用空格代替冒号，也支持放在整段分享文案末尾，例如 `...视频链接 分类 测试`。
- 已收录链接带新分类再次发送时只更新归档，不重复下载；仅补备注不会重置旧分类。
- 每条视频独立文件夹：视频、封面、双语文案；平台有原版字幕且勾选时再保存原版字幕。完成卡片可直接“打开文件夹”。
- 同一明确视频 ID/规范化链接去重；尚未解析的不同短链如果指向同一视频，不承诺全部自动识别为重复。
- 暂停自动下载后仍收录链接，当前任务继续结束。已收录队列持久保存；失败可在软件重试。

## 离线与后台边界

关闭主窗口后保留托盘收件；从托盘退出、关机、休眠或断网期间不会下载。重新运行后尝试读取绑定后仍可读取的机器人私聊历史；没有读取权限、消息过期/删除或视频失效时无法保证补回。失败不会静默跳过历史游标。

原视频下载与 AI 接口翻译在原生后台线程运行，不依赖网页计时器。本地翻译使用原有 WebView/WASM 工作线程，隐藏窗口后的持续执行仍需 Windows 实机验收。不要把“有托盘代码”当成后台全部功能已验收。

解除配对保留下载文件和旧任务记录，并清除两份恢复快照中的当前应用凭证。重新绑定产生新的配对身份，不自动混入上一次账号的任务。

## 开发检查

在 `desktop`：`npm test`、`npm run build:web`。

在 `desktop/src-tauri`：`cargo test --lib`、`cargo check --examples --features team-smoke`。

`team-smoke` 是原生集成测试示例：使用独立标识 `org.yinglian.personal-smoke` 和 `F:/820/yinglian-personal-qa`，输入是模拟飞书消息，但下载、ASR、AI 翻译和文件写入均为真实引擎。正常发行版不包含这些测试入口。

`personal-preview` 是独立界面验收示例，标识 `org.yinglian.personal-preview`；不覆盖已安装版本。发布前仍必须用真实专用机器人完成配对、手机收发、离线补收、重连和两个账号隔离测试。
